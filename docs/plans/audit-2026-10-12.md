# Repo audit — 2026-10-12

A one-shot audit of the whole repo, done after the 0.9.0 release. Four
reviewers each read one high-risk area: main-process IPC, the MCP
server, the save pipeline, and the agent plus code that shouldn't exist.
Claims marked **(checked)** were confirmed in the code; the rest were
traced through the code but not run.

**What this repo does:** Scamp is a desktop design app built on
Electron. You draw on a canvas and it saves real React code (TSX and
CSS module files) to your project folder. When an agent or a person
edits those files, the canvas reloads. A built-in AI agent and a local
MCP server let agents read and edit the project.

**Load assumed:** one person, one open project, but several writers on
the same files at once: the canvas, the built-in agent, an agent in the
terminal, and an outside MCP client. The renderer shows imported web
pages, so it's treated as only partly trusted: a bug there should not
reach your whole disk.

Check a box when the fix is merged.

## Must fix

### 1. Deleting or reading a snapshot can reach any folder

- [x] Fixed — `snapshotDirFor` refuses any id but `[\w-]+`; every snapshot handler checks `projectPath` (and the read's page paths) against the open project.

`src/main/ipc/snapshotOps.ts` (`deleteSnapshot`, `readSnapshotPage`), **(checked)**

- **What this is:** handlers that delete a saved snapshot or read one
  page from it. The renderer sends the snapshot id.
- **Problem:** delete runs `rm -rf` on `.scamp/snapshots/<id>` before
  checking the id is real. An id of `../../..` deletes the project or a
  folder above it. The read builds a path the same way and can return
  any file, such as `~/.ssh/id_rsa`.
- **Fix:** reject ids that don't match `/^[\w-]+$/` or aren't in the
  index; check `projectPath`, `tsxPath`, and `cssPath` are inside the
  active project.
- **If we skip it:** one renderer bug can wipe a folder outside the
  project.

### 2. Many file handlers never check which folder they work in

- [x] Fixed — `assertInsideActiveProject` added to the page, component, routes, context, preview (open, restart), HTML export, ProjectRead, and ProjectMigrate handlers; duplicate and rename check the source page name; image copy only takes image files; ProjectOpen only opens folders from the picker, the start screen's list, or a test's auto-open (`allowProjectOpen` in `pathContainment.ts`). Component thumbnails stay unguarded: they can land just after a project closes.

`componentOps.ts`, `pageOps.ts`, `pageRename.ts`, `image.ts`,
`preview.ts`, `project.ts`, and others

- **What this is:** handlers that delete a component or page, rename a
  page, copy an image, open a preview, and open a project.
- **Problem:** they trust `projectPath` and page names from the
  renderer. Delete-component runs `rm -rf <any folder>/components/<Name>`.
  Rename with a `../` name deletes files. Preview runs `npm install` in
  any folder. Open-project accepts your home folder, which moves the
  "inside the project" boundary so every other check stops protecting
  anything.
- **Fix:** `assertInsideActiveProject(args.projectPath)` at the top of
  each handler; page names checked against `PAGE_NAME_RE`; open-project
  accepts only folders main itself handed out (folder picker, a new
  project, the recent-projects list).
- **If we skip it:** every other path check can be sidestepped.

### 3. Any link a page opens is launched by the operating system

- [x] Fixed — only `http:`, `https:`, `mailto:`, and `tel:` reach `shell.openExternal` (canvas link badges open mail and phone links).

`src/main/index.ts` window-open handler, **(checked)**

- **What this is:** when the main window tries to open a window, Scamp
  passes the URL to `shell.openExternal`.
- **Problem:** any scheme is accepted. A `file:///…/x.exe` or `smb:`
  link gets opened by the OS, which can run a program.
- **Fix:** allow only `http:` and `https:`, as `previewWindow.ts`
  already does.
- **If we skip it:** one click in a crafted imported page can launch a
  program.

### 4. On Windows, a route file name can escape the project

- [x] Fixed — `routeFilePath` also refuses `\` and `:`.

`src/main/ipc/routeOps.ts` (`routeFilePath`)

- **What this is:** the handler that writes a route file from a name
  the renderer sends.
- **Problem:** the name check splits on `/` only. On Windows,
  `..\..\AppData\…\Startup\x.js` passes, and the write lands in the
  Startup folder, which runs at login.
- **Fix:** resolve the full path and check it stays under `routes/`.
- **If we skip it:** a path bug on Windows becomes code that runs at
  every login.

### 5. A restore runs even when its safety copy failed

- [ ] Fixed

`snapshotOps.ts` (`restoreSnapshot`), **(checked)**

- **Problem:** `createSnapshot` returns `null` on error (for example a
  full disk) and the restore ignores it, then copies over your files
  with no way back.
- **Fix:** stop the restore when `createSnapshot(...)` returns `null`.
- **If we skip it:** a restore on a full disk loses the current work.

### 6. Quitting with Cmd+Q can lose the last edit

- [ ] Fixed

`src/main/index.ts` (`before-quit`, `performShutdownCleanup`), order
checked, not run

- **Problem:** `before-quit` runs cleanup, including `disposeWatcher()`,
  before the windows close. The window's last debounced write then
  arrives with no active project and is refused.
- **Fix:** close windows first and clean up after, or have the renderer
  flush and wait (with a timeout) before cleanup.
- **If we skip it:** the last fraction of a second before Cmd+Q never
  reaches disk.

### 7. Edits made while paused for an agent are never written, and the status says "Saved"

- [ ] Fixed

`syncBridge/writeIfDirty.ts`, `syncBridge/quietReconcile.ts`

- **Problem:** the "canvas changed during the pause" flag is only set
  during the short chokidar quiet window. On resume, Scamp skips the
  write and shows **Saved**; the edit lives only in memory, and the
  next agent write reloads over it.
- **Fix:** in the agent-active early return in `writeIfDirty`, set
  `ctx.canvasChangedDuringQuiet = true`.
- **If we skip it:** agent users lose edits the app says are saved.

### 8. Switching page while paused loses the edits on the page you leave

- [ ] Fixed

`useActiveTarget.ts` (`persistActiveSource`), `storeSubscription.ts`

- **Problem:** while paused, the outgoing write is skipped but the
  unsaved code is kept as if it were on disk. Coming back, Scamp thinks
  nothing changed, and the next edit's merge reverts the earlier one.
- **Fix:** let the flush on leaving a page skip the pause check; the
  compare-and-swap check plus merge already make that safe.
- **If we skip it:** same silent loss as 7.

### 9. A failed save makes the next save undo it

- [ ] Fixed

`writeIfDirty.ts`, `writeDispatch.ts`

- **Problem:** the "last written" cache is advanced before the write
  succeeds and never rolled back. The next edit is refused, and the
  merge treats old disk as truth, undoing the failed edit. **Retry**
  has no conflict handler, so the status can stick on **Saving…**.
- **Fix:** on error, restore `ctx.lastSerialized*` to the expected
  values; give Retry the normal conflict handler.
- **If we skip it:** one brief disk error becomes lost work.

### 10. Leaving a snapshot preview can write the preview over the live page

- [ ] Fixed

`syncBridge/quietReconcile.ts` (`makeFlushDebouncedWrite`), guard
missing **(checked)**

- **Problem:** the normal save path skips writes during a preview; the
  flush on page switch or project close doesn't, and writes the
  snapshot's code to the live files.
- **Fix:** `if (state.snapshotPreview !== null) return;` at the top.
- **If we skip it:** previewing an old version then clicking another
  page replaces the current page with the old one.

### 11. Opening a second project erases the first project's agent memory

- [ ] Fixed

`src/main/ipc/agent.ts` (`conversationFor`), **(checked)**

- **Problem:** it calls `reset()`, which empties model history, and the
  turn-end save writes that empty history next to the full transcript.
- **Fix:** `c.agent.cancel()` instead of `reset()`.
- **If we skip it:** the agent forgets a conversation still on screen.

### 12. Closing or switching a project doesn't stop a running agent turn

- [ ] Fixed

`agent.ts`, `mcp/lifecycle.ts`, `agentToolResponder.ts`

- **Problem:** nothing cancels the turn, so it keeps spending the API
  key, and its edits go to whatever is open — with a page named `home`
  in both projects, A's edits land on B.
- **Fix:** cancel all open conversations next to the `stopMcp()` calls
  in `startMcpForProject` and at shutdown.
- **If we skip it:** edits land in the wrong project.

### 13. The agent can stay "busy" until the app restarts

- [ ] Fixed

`src/main/agent/session.ts`, `store/agentSlice.ts`, **(checked)**

- **Problem:** if loading the key throws, the busy mark is never
  cleared; every later send returns "busy" and the spinner never stops.
- **Fix:** `await deps.getProvider().catch(() => null)` in the session;
  `try/finally` around `agentSend` in the slice.
- **If we skip it:** the agent panel looks dead until restart.

### 14. Imported page source is kept in a shared temp folder and trusted

- [ ] Fixed

`src/main/importSourceStore.ts`

- **Problem:** the folder is in shared `/tmp` at a predictable name,
  readable by other users. Another account can plant a record pointing
  at `~/.ssh/id_rsa`, and `scamp_get_import_source` reads it back.
- **Fix:** build file paths from the folder, not the stored record;
  create it with `mode: 0o700`, or move it under
  `app.getPath('userData')`.
- **If we skip it:** on shared Linux machines, others can read imported
  pages and steer the agent to your files.

## Should fix

### 15. A CSS patch and a page write can drop each other's changes

- [ ] Fixed

`src/main/ipc/file.ts`

- **Problem:** the patch reads, edits, and writes with no per-file
  lock; a page write in between means the last write wins.
- **Fix:** a promise chain per path around both handlers.

### 16. Some files aren't written safely, and the snapshot list can lose entries

- [ ] Fixed

`themeOps.ts`, `designMdOps.ts`, `snapshotOps.ts`, `settingsOps.ts`

- **Problem:** in-place writes; a crash leaves a cut-off file. A cut-off
  `snapshots.json` reads back as empty and hides all history. Two
  snapshots at once overwrite each other's index update.
- **Fix:** use the existing `atomicWrite`; serialize index updates.

### 17. "Undo AI session" can miss an edit

- [ ] Fixed

`src/main/ipc/agent.ts`

- **Problem:** with two edits at once, the second sees "snapshot taken"
  and writes before the copy finishes, so undo won't revert it.
- **Fix:** keep the snapshot promise (`snapshotReady ??= …`) and await
  it in every edit.

### 18. Renaming or deleting a component can rewrite pages from old code

- [ ] Fixed

`useComponentManagement.ts`

- **Problem:** pages are rewritten from a possibly stale copy without
  the expected-content check. Depends on how chokidar reports renames
  per OS (not confirmed).
- **Fix:** read pages fresh with `readProject` and pass expected
  content.

### 19. The `EDITS` table is written twice

- [ ] Fixed

`syncBridge/agentToolResponder.ts`, `lib/agentHeadless.ts`

- **Problem:** identical copies; a tool added to one only works in one
  mode.
- **Fix:** export once from `@lib/agentEdits`.

### 20. `zundo` is installed but never used

- [ ] Fixed

`package.json`, **(checked)**

- **Fix:** remove it and the stale comment in `saveStatusSlice.ts`.

## Left out (smaller)

- `parsePx` duplicates `parsePxOrNull` (about 7 lines).
- The MCP server decodes request bodies chunk by chunk, which can
  corrupt non-ASCII text.
- MCP batches have no size limit.
- MCP agent config files are written through symlinks; a tracked
  `.mcp.json` can commit the token.
- The `scamp-asset` protocol accepts `Origin: null`.
- MCP clients could hit another program on Scamp's fixed port while
  Scamp is closed.

## Verdict

Fix the IPC path checks first (1–4), then the save-pipeline losses for
agent users (7–10, 6). Items 5, 7, 10, 11, and 13 are each about one
line.

**Lean:** -19 lines, -1 dependency possible.

**Not checked:** nothing was run, so 6, 8, 12, 15, and 18 are traced,
not reproduced. Not read: the import pipeline, `generateCode` /
`parseCode` internals, auth handlers, migrations, `mcpResponder.ts`,
symlinks inside a project. A fully compromised renderer already has a
shell through the terminal feature, so 1–4 matter most for partial
bugs.
